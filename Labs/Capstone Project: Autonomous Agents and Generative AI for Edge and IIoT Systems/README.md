# Capstone Project: Smart Traffic Management Edge AI
### The Problem
In modern urban environments, traditional traffic light systems often operate on rigid timers that do not account for real-time traffic flux, leading to unnecessary congestion and increased vehicle emissions. The objective of this capstone project was to address this inefficiency by designing an AI-driven autonomous agent capable of optimizing traffic flow at intersections. The core challenge was to develop a system that could collect real-time vehicle density data, process it at the "edge," and autonomously adjust light cycles to maximize throughput.  
### My Approach and Methods
To solve this, I implemented an end-to-end Edge AI pipeline:Edge AI Deployment: I trained a machine learning model using TensorFlow and converted it into a lightweight .tflite format to ensure efficient local execution on an edge device.  Autonomous Inference: I developed a Python script (edge_traffic_agent.py) utilizing the ai-edge-litert interpreter. This script simulates camera data capture to input vehicle counts into the model, which then outputs confidence-backed decisions like GREEN_NS (Green North-South) or GREEN_EW (Green East-West).  IoT Messaging and Visualization: The agent uses the MQTT protocol to transmit real-time JSON payloads containing sensor data and AI decisions to a central system. For monitoring, I configured a Node-RED dashboard that subscribes to the telemetry topic to visually parse and display the agent's autonomous commands.  
### The Results
The project successfully demonstrated a fully functional autonomous architecture.Decision Accuracy: The AI agent accurately identified vehicle density and executed appropriate actions (e.g., GREEN_NS with 0.90 confidence) in real-time.  Operational Connectivity: Telemetry was seamlessly transmitted via MQTT and reflected instantly on the Node-RED dashboard, proving the system's reliability for smart city applications.System Meaning: This project validates that local AI processing can reduce the latency and bandwidth requirements of traditional cloud-based traffic management, offering a scalable framework for future smart-grid or intersection hardware.
### What I Learned
Deployment Workflows: I learned the critical importance of distinguishing between training environments (Cloud/Google Colab) and execution environments (local edge agents).Protocol Implementation: I gained hands-on experience with industrial communication protocols like MQTT and how to handle real-time JSON data streams.  Hardware Simulation: I understood how to bridge the gap between Python-based simulations and potential hardware integrations like ESP32 or live camera feeds.
### Challenges Faced
Environment Mismatches: I encountered a ValueError when attempting to run the local edge script within the cloud-based Google Colab environment. I resolved this by properly isolating the workflow: training in Colab and running the LiteRT interpreter locally.MQTT Connection Quirks: I faced ConnectionRefusedError (Errno 61) because the local Mosquitto broker was inactive and due to macOS networking issues with "localhost" routing. I overcame this by manually starting the service via Homebrew and explicitly mapping the broker IP to 127.0.0.1 in the code.
